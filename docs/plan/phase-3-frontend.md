# Phase 3 — Frontend Dashboard

**Goal:** the React dashboard: a grid of independent session widgets with live streaming
transcripts, interactive permission prompts, interrupt, reconnect-with-replay, and a
session-creation dialog backed by templates. Production build served from the Spring
Boot jar; dev mode via Vite proxy.

**Estimated effort:** 2–3 days.

## Stack & layout

- Vite + React 19 + TypeScript (strict), `react-grid-layout` for the widget grid,
  `zustand` for state (one store slice per session), `react-markdown` + `remark-gfm`
  for transcript rendering, no CSS framework beyond CSS modules (keep deps thin).
- Protocol types generated by hand-mirroring `docs/PROTOCOL.md` into
  `frontend/src/protocol.ts` (single file, kept in lockstep; a codegen step is not
  worth it at this size).

```
frontend/src/
├─ api/            # REST client (fetch + token), WsSession (reconnecting WebSocket)
├─ store/          # zustand: sessions, per-session transcript model, layout persistence
├─ components/
│  ├─ Dashboard.tsx          # grid, add-widget button, layout save to localStorage
│  ├─ SessionWidget.tsx      # header / transcript / prompt card / input bar
│  ├─ Transcript.tsx         # virtualized list of turn blocks
│  ├─ TurnBlock.tsx          # streamed markdown, tool-call collapsibles
│  ├─ PermissionCard.tsx     # approve / edit-input / deny
│  ├─ CreateSessionDialog.tsx# name, branch, base, template picker, overrides,
│  │                         # ecosystem-context toggle (prefilled parent path, editable/clearable),
│  │                         # skills picker (skills-root library + free-form path/repo-URL entries)
│  ├─ TemplateManager.tsx    # CRUD screen for templates
│  └─ TokenGate.tsx          # token entry, stored in localStorage, attached everywhere
└─ App.tsx
```

## Key behaviors

### Capabilities-driven rendering
Provider-dependent controls — permission-mode toggle (and which modes it cycles),
thinking preset, plan-approval card, skills/agents pickers, fallback-model field —
render only when the session's `capabilities` (from the REST detail) declare support.
Nothing in the components hardcodes "Claude"; a poorer adapter simply shows fewer
controls.

### Transcript model (client-side reduction)
WS events reduce into a turn-structured view model, not a raw event list:
- `stream_delta` appends to the open assistant block (markdown re-rendered incrementally,
  throttled to ~30 fps). `thinking` deltas render into a collapsed, visually muted
  "thinking…" section per turn (expand to read; global show/hide toggle in settings).
- `tool_started`/`tool_result` render as a collapsible row (name + input summary;
  expand for full input/output; error results highlighted).
- `permission_request` renders `PermissionCard` inline **and** pins the widget into
  `WAITING_INPUT` styling (amber border). Approve → `permission_response` allow;
  "Edit command" opens the input JSON (or command string for Bash) for modification →
  allow with `updatedInput`; Deny asks for an optional reason.
- **Plan approval is a special-cased permission**: an ExitPlanMode `permission_request`
  renders the plan markdown full-width with "Approve & execute" / "Keep planning"
  instead of the generic card.
- `turn_complete` closes the turn with a footer: duration, cost, token usage.
- `state_changed` drives the header badge (IDLE / RUNNING / WAITING / CRASHED / …).

### Reconnect & replay
- `WsSession` reconnects with exponential backoff, always passing `afterSeq` =
  highest seq seen; the store is built to be replay-idempotent (seq-gated appends).
- Widget shows `Disconnected — reconnecting…` overlay; a full page refresh rebuilds
  every widget from replay alone (this is the acceptance test for the whole model).

### Widget chrome
- Header: state dot + name, branch, model chip, **permission-mode toggle** (cycles
  Ask edits → Auto-accept edits → Plan; sends `set_permission_mode`, reflects
  `permission_mode_changed` — distinct colors so auto-accept is unmistakable),
  ecosystem-context chip (🌐 shown when a context dir is attached; tooltip lists the
  paths), cost-to-date, kebab menu (interrupt, resume when CRASHED, close).
- Close flow: menu → dialog calls `DELETE ?dirty=fail` first; on 409 shows the dirty
  files and offers Commit (message input) / Stash / Discard (destructive-styled,
  double-confirm) — mirroring the Phase 2 API exactly.
- Input bar: multiline textarea, Enter=send / Shift+Enter=newline, Stop button issues
  `interrupt`. **Stays enabled while RUNNING**: messages sent mid-turn show as queued
  chips above the bar (deletable until dispatched), mirroring backend queueing.
- Create dialog: when the chosen template has a `kickoffPrompt`, its `{{placeholders}}`
  become form fields; behavior overrides section exposes thinking level (Off/Low/
  Medium/High presets), max turns, cost budget, instructions, fallback model.

### Build integration
- Dev: `vite dev` on 5173 proxying `/api` and `/ws` to 8080 (ws proxy enabled).
- Prod: `frontend-maven-plugin` runs the Vite build in the Maven package phase, output
  into `target/classes/static/` → single runnable jar. SPA fallback controller maps
  unknown non-API paths to `index.html`.

## Out of scope
- Mobile layout polish, git status/diff panel, model switching mid-session (Phase 5);
  auth beyond the shared token; multi-repo.

## Definition of Done
- [ ] `mvn package` produces one jar that serves the dashboard, REST and WS on 8080.
- [ ] Token gate: wrong token → clear error, nothing loads; correct token persists across refresh.
- [ ] Create dialog lists branches and templates; creating a session shows provisioning states live and lands in IDLE.
- [ ] Skills picker: selecting a library skill plus a free-form repo URL yields a session whose detail lists the resolved skills; invoking one from the input bar works.
- [ ] Permission-mode toggle: switching to Auto-accept mid-session makes the next edit apply without a card; the toggle state is visually unmistakable and survives refresh.
- [ ] Plan flow: a `plan`-mode session shows the rendered plan with Approve & execute / Keep planning; approval transitions into execution.
- [ ] Thinking sections render collapsed and expandable; global hide toggle works.
- [ ] Queueing: two messages sent during a long turn appear as chips, dispatch in order; deleting a chip before dispatch removes it.
- [ ] Kickoff template: placeholders appear as form fields and the filled prompt fires as the first turn.
- [ ] Streaming renders incrementally (visibly token-by-token) with markdown formatting; tool calls collapse/expand; costs shown per turn and cumulatively.
- [ ] Permission card: approve, deny, and edit-command paths all verified against a real Bash request.
- [ ] Stop button interrupts a long generation; widget returns to IDLE.
- [ ] Hard refresh mid-conversation restores every widget's full transcript and state from replay.
- [ ] Two browser tabs show the same session in sync.
- [ ] Close flow with dirty worktree walks through commit/stash/discard correctly.
- [ ] CRASHED widget offers Resume; resuming continues the conversation in place.
- [ ] Grid layout (positions/sizes) survives refresh via localStorage.
- [ ] Reachable and usable from a second device on the LAN (with token) — the stated deployment target.

## Manual test script

| # | Action | Expected |
|---|---|---|
| 1 | Open dashboard, enter wrong token | error, no data; correct token → session list |
| 2 | New Session: pick template, branch `feat/ui-test`, base `main` | widget appears, states progress to IDLE |
| 3 | Send "summarize this repo" | streaming markdown, tool rows, turn footer with cost |
| 3b | Ask "how does service X (a sibling in the ecosystem folder) call this service?" | answer cites the sibling's code; context chip visible in header |
| 4 | Send prompt requiring Bash | amber permission card |
| 5 | Click Edit, change command to `echo edited`, approve | tool result shows `edited` |
| 6 | Long prompt, click Stop mid-stream | generation halts, IDLE |
| 6b | Toggle header to Auto-accept, request a file edit; toggle back, request another | first applies silently, second shows the card |
| 6c | Send two more messages while a turn runs | queued chips shown, then dispatched FIFO |
| 6d | Create session from a kickoff template (e.g. "Bugfix: {{ticket}}") | placeholder field in dialog; session starts by working the filled prompt |
| 7 | F5 during an active response | transcript fully restored, live stream continues |
| 8 | Open same session in second tab | mirrored in real time |
| 9 | `kill -9` the sidecar from a terminal | widget shows CRASHED + Resume; Resume works |
| 10 | Close widget after editing a file in worktree | dirty dialog; choose Stash; widget gone, stash present |
| 11 | Open dashboard from phone/laptop on LAN | fully functional |
| 12 | Drag/resize widgets, refresh | layout preserved |
